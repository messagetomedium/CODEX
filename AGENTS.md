# Codex Cloud rules — Matryoshka Godot Web

1. Прочитай `GDD_Matryoshka_v1.0.md`, `SCREEN_SCRIPT_UI_v1.0.md`, `TECH_ARCHITECTURE_v1.0.md`, `CODEX_TASKS_v1.0.md`, `data/config/*.json`, `references/goal_scene_original.png` и `GITHUB_SETUP.md` перед изменениями.
2. **Движок фиксирован:** Godot 4.5.2 standard, GDScript, Compatibility renderer, Web export без потоков. Не Phaser/TypeScript/Vite, не Unity, не Unreal, не C#/.NET. Уже есть `project.godot` и GitHub Actions; не создавай вложенный второй проект.
3. Следуй GDD как неизменной спецификации геймплея. При противоречии остановись и укажи конкретную коллизию требований, не выдумывай правила.
4. **Два типа игровых экранов:** MAIN_MENU и GAME_LEVEL. Инструкция, голы/неудачи, intermediate/final results и ошибка mic — только UI overlay поверх того же уровня. Встраиваемые `.tscn` сцены для UI разрешены, но не как отдельные fullscreen pages.
5. По прямому запросу владельца реализованы **«Забить гол», раунды 1–3** (в каждом 3 гола/6 попыток). После победы доступны следующий раунд, после третьей — завершение игры. Две другие карточки disabled. Главное меню без общего названия проекта; у каждой карточки зона иллюстрации, под ней название, ниже маленький слоган. Выбор мышью. Intro 3 инфографики в один горизонтальный ряд только при входе из меню, не при каждом повторе.
6. Композиция blockout строго по `references/goal_scene_original.png`: плоские спрайты/примитивы, вид от первого лица, статичная камера, ворота по центру, мяч снизу, защитников до 1/2/3 по раундам, только перед воротами, и goalkeeper по X с повторяемым рисунком движения. Референс нельзя использовать целиком как игровой фон.
7. Тексты читать из `res://data/config/ui.ru.json`, параметры механики, layout и анимаций из остальных `res://data/config/*.json`. В Godot Web не использовать HTTP-fetch путей `public/`.
8. Вся UI-анимация **только программно через Godot Tween**, отдельный именованный профиль каждого UI-блока в `data/config/ui_animations.json`. Нет GIF, видео-оверлеев, hardcoded длительностей. При `durationMs=0` показывать состояние мгновенно.
9. Без воспроизводимого аудио: **никаких саундтреков, сигналов мяча, микрофонного мониторинга**, фонового звука или записи речи. Только анализ mic в browser Web Audio API через Godot `JavaScriptBridge` (Task 2), без передачи голоса в сеть.
10. Настоящий микрофон требует HTTPS (Pages) и ручного browser-теста. До Task 2 не объявляй mic реализованным. Для headless тестов отдельный debug input; публичное управление клавиатурой недоступно.
11. Не меняй/не удаляй GDD, сценарий UI, текстовые JSON, референс или workflow без явной потребности и пояснения. Три раунда, 3 гола/6 попыток в каждом, лимиты защитников 1/2/3 и скорость защитника 2,6 секунды в третьем согласованы владельцем; остальное — параметры балансировки. Мягкие касания краем мяча допускают гол; центральный контакт с рамой/игроком остаётся столкновением.
12. **Работай по очереди:** первый запрос — только Tasks 0 и 1. После задачи запускай `python3 tools/validate_handoff.py`; при наличии Godot — headless import/test/export; сообщай результаты честно и не утверждай о работающей веб-публикации до успешного Actions deploy.
13. Все изменения сдавать через GitHub branch/pull request или описывать точный коммит. Автоматическая публикация включается после merge в `main` при настроенном Pages. Не переписывай workflow ради «упрощения», если текущая сборка работает.
14. Не переходи к следующей игровой задаче без подтверждения пользователя; в финале каждой итерации укажи изменённые файлы, команду/лог проверки, что не проверено в браузере и ссылку на Pages при наличии.
