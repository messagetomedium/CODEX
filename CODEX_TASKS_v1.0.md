**Основная цель:** высококачественный 2.5D browser-blockout «Забить гол», при сохранении меню из трёх мини-игр и общих UI-попапов. Технология зафиксирована: **Godot 4.5.2 standard + GDScript + Web**, Godot Web export через GitHub Actions. Сначала рабочая композиция, затем микрофон/механика/полировка.

## Task 1. Главное меню и blockout поля — первый промпт

- Заменить временную `Bootstrap.tscn` как точку входа на `MainMenu.tscn`; создать `GoalLevel.tscn` и общую UI-архитектуру из `TECH_ARCHITECTURE_v1.0.md`.
- **Главное меню:** три карточки в горизонтальном ряду, иллюстрация-заглушка сверху, название снизу, короткий слоган ниже. Общего названия проекта нет. Активна только «Забить гол», остальные disabled и не кликаются. Выбор мышью.
- **Игровая сцена:** фронтальный блок-дизайн поля по `references/goal_scene_original.png`: ворота по центру, мяч крупно снизу, вратарь в створе, плоский защитник. Строго неподвижная камера. Пока без физики и без микрофона.
- При выборе игры показывается **поле + по центру общий интро-попап** (он не является отдельным экраном). 3 пункта инфографики строго в ряд, временные кодовые пиктограммы, кнопка «Начать»; после нажатия пока можно показывать честное диагностическое состояние «Микрофон будет подключён в следующей задаче», но **не имитировать уже рабочий микрофон**.
- Глобальная кнопка «Сброс» возвращает в меню из любого текущего состояния, включая intro. Нет музыки/эффектов.
- Тексты читать из `res://data/config/ui.ru.json`, координаты UI и анимации из конфигов. Все переходы UI программные через Godot Tween, без GIF/видео или статически зашитых анимаций.
- Обновить `project.godot` main_scene. После task сделать импорт и экспорт Web, проверить .html/.wasm/.pck, предоставить URL публикации или путь публикации через Actions, если URL ещё не появился.

**Критерий:** на веб-сайте реально появляется меню, кликается «Забить гол» и виден блок-дизайн с инструкцией. Остальные игры отключены. Начальный popup перекрывает только часть поля. Никаких лишних полноэкранных экранов. Codex ждёт подтверждения перед Task 2.

## Task 2. Микрофон и debug-адаптер

- Реализовать `web/microphone_bridge.js`: `getUserMedia` + `AudioContext` + `AnalyserNode`, без output и сети.
- Из GDScript взаимодействовать через `JavaScriptBridge` при `OS.has_feature("web")`, отслеживать асинхронный `pending/active/error`, токен сброса, stop/dispose, request/retry.
- Автоматическая адаптация к фоновому шуму без отдельного экрана/ручной калибровки; катание определяется продолжительной тихой громкостью; короткий резкий пик — отдельное событие удара с release/cooldown. В HUD шкала громкости.
- Заложить интерфейс источника данных, подменяемый DebugVoiceInput только для `?debug=1` или локально при явном debug-режиме. W = катить, Space = удар, 1/2/3 = сила.
- **Обязательна ручная проверка владельцем в опубликованном браузере**: permission, работа RMS, запрет доступа, retry, отсутствие звука. Codex не заявляет, что тест микрофона пройден, если нет реального browser microphone.

## Task 3. Мяч, защитник, вратарь и коллизии

- Внести параметры из `data/config/gameplay.json` с пониманием, что числа тестовые.
- Реализовать `progress`/flight arc/scale; катание за 3–5 с при достаточно уверенном тихом голосе, почти моментальная остановка; слабый удар приземляется до ворот и попытка продолжается.
- Вратарь постоянно движется только X между границами, защитник — один за раз из края в край по X; защитник перехватывает даже летящий высоко мяч при экранном пересечении, вратарь — при пересечении goal line по X. Возможен гол катанием. Камера неподвижна.
- Отделить чистую игровую логику от визуальных Node2D и случайного спавна; добавить headless-тесты.

## Task 4. Счёт, оверлеи и все результаты

- Попытка начинается при первом реальном движении мяча; 3 гола или шесть **разрешённых** попыток.
- После гола: кодовая реакция сетки, праздничный UI, небольшая надпись «ГОЛ!», счёт и случайный короткий совет. После fail: мяч останавливается, локальная подпись в безопасном месте без перекрытия ворот, игроков и HUD. Продолжительность 2–3 с.
- Все оверлеи ставят на паузу игровую логику и voice control, декоративный фон может продолжить анимацию. Создать переиспользуемый `GameInfoPopup` с предусмотренным, но пока не вызываемым intermediate-result вариантом.
- Финальный центральный popup: случайная короткая реплика по числу голов (3/2/1/0), голы и потраченные попытки, три кнопки «Повторить», «Главное меню», disabled «Следующий уровень». Повтор без повторной инструкции.

## Task 5. Полировка программных UI-анимаций

- Все 21 профиль из `data/config/ui_animations.json` подключены через единую библиотеку Godot Tween и поэлементные ID. При смене `goalEvent.tip.enter.durationMs` меняется только анимация подсказки гола; при смене `failEvent.callout.enter.durationMs` меняется только надпись неудачи.
