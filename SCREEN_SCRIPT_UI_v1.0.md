# «Матрёшка» — сценарий интерфейса и внутриигровые тексты

**Версия:** 1.0 · **Для прототипа:** главное меню + «Забить гол», раунд 1.

## 1. Как менять тексты без правки программного кода

**Единый источник всех пользовательских фраз:** `data/config/ui.ru.json`. Каждая надпись имеет стабильный `ID`; разработчик получает текст по ID, **не зашивает строку в GDScript**. Редактировать нужно только значения `title`, `description`, `text`, `subtitle`, `phrases`, `label` и т. п.; ID и поля подстановок `{goals}`, `{goalTarget}`, `{attemptsUsed}`, `{maxAttempts}`, `{round}` **не менять**.

Пример: отредактировали `goal.intro.objective` в JSON, сохранили файл, обновили игру — текст изменился без изменений исходного кода (в Godot Web JSON входит в PCK; после правки требуется новая экспортная сборка). Чтобы получить актуальную таблицу текстов ниже, вызвать `python tools/sync_ui_docs.py`. **Показанные ниже строки — автоматически обновляемое представление этого JSON**, а не второй отдельный источник истины.

Второй независимый слой редактирования — `data/config/ui_animations.json`: для каждого элемента собственные программные анимации. Положение: `data/config/ui_layout.json`. Результат: можно поменять **фразу, положение или анимацию конкретного блока независимо** друг от друга и от игровой механики.

## 2. Постоянная иерархия UI

- Полноэкранные экраны существуют только двух типов: `MAIN_MENU` и `GAME_LEVEL`. Остальные компоненты — оверлеи, **никогда не отдельные экраны**.
- На уровне всегда виден HUD: раунд, голы, использованные попытки, маленький индикатор голоса, глобальный «Сброс».
- Оверлей-инструкция существует **перед входом в мини-игру из меню**. Перед каждым раундом и после «Повторить» его **не показывать**.
- Один общий шаблон `GameInfoPopup` имеет варианты `intro`, `goal_event`, `fail_event`, `final_result`, `intermediate_result` (на будущее) и `microphone_error`. Для короткой неудачи показывается **локальная подпись** в составе общей системы оверлеев, а не крупная центральная плашка.
- Открытый оверлей ставит **игровую механику и управление голосом на паузу**. Декоративный фон может продолжать двигаться. Во время паузы никаких скрытых счётов/столкновений.
- Все **UI-анимации только кодом**, с отдельными профилями анимации каждого блока. Запрещены анимированные GIF/видео для интерфейса; будущие мини-демонстрации инструкций тоже программные.

## 4. Инфографика на стартовом попапе

**Одна горизонтальная строка из трёх ячеек**, без длинного текста. В каждой: графическая область → короткий заголовок → одно короткое пояснение. Задача «3 гола за 6 попыток» — отдельно над строкой. В blockout изображения иконок рисуются простыми программными примитивами.

У каждого пункта стабильный ID: `roll`, `kick`, `timing`. Данные по каждому находятся в массиве `goal.intro.instructions` JSON; поля `visual.mode`, `visual.iconId` и `visual.animationId` позволяют позднее заменить **иконку на кодовую мини-анимацию** отдельно для одного пункта. UI-разметку остальных пунктов не менять.

Режим `icon` — статическая иконка. Режим `codeAnimation` — мини-сцена внутри того же прямоугольника, где движение мяча/дуга/защитник управляются игровым кодом и `intro.visual.codeAnimation` в конфиге. **Никаких встроенных видео или GIF.**

## 5. Размещение коротких надписей и художественный тон

**После гола:** эмоциональный компактный оверлей, большой «ГОЛ!» плюс счёт и совет. Совет звучит как фраза живого тренера или комментатора, но **содержит точное полезное действие** на следующую попытку. Избегать ложных советов («целься левее», «ударь выше защитника»), поскольку X игрок не контролирует, а защитник перехватывает даже высокую дугу.

**После неудачи:** не затемняем всё поле и не показываем центральный прямоугольник. Маленькая подпись в одном стиле с остальными уведомлениями, с коротким мягким появлением и уходом, размещается в свободной области **не поверх ворот, мяча, футболистов, HUD и глобальной кнопки «Сброс»**. Место выбирается программно из кандидатных якорей в `data/config/ui_layout.json`; учитываются актуальные bounds защищаемых объектов.

**Подсказки:** библиотека `goal.tips` содержит 12 коротких реплик. При голе случайно выбирать одну, **не повторять последнюю, если есть другие**. Учитывать смысл: совет должен помогать управлять голосом и таймингом. При неудаче допускается фиксированная короткая подсказка, привязанная к причине, чтобы текст был понятнее.

## 6. Финальные результаты: эмоциональная фраза, а не строгая «оценка»

Шкала определяется **числом голов**. Три гола — всегда победа; два, один или ноль после шестой попытки — мягкие варианты приглашения попробовать ещё раз. У каждого из четырёх результатов есть **по три альтернативные короткие фразы**, которые выбираются случайно из соответствующего пула. Отдельного экрана победы/поражения нет — **только общий финальный попап над полем**. Глобальная кнопка «Сброс» активна и здесь.

- `goal.results.tiers.3` — три гола (победа, восторженный комментарий).
- `goal.results.tiers.2` — два гола (почти удалось).
- `goal.results.tiers.1` — один гол (поддержка).
- `goal.results.tiers.0` — ни одного (спокойный призыв повторить).

У всех вариантов общий набор статистики: `Голы: {goals}/{goalTarget}`, `Использовано попыток: {attemptsUsed}/{maxAttempts}`. Общие кнопки: «Повторить», «Главное меню», **«Следующий уровень» (disabled)**.

## 8. UI-анимации, которые должен написать Codex

Вся анимация **интерфейса — программная**, не набор визуальных ассетов. Использовать `UIAnimationController` и профили из `data/config/ui_animations.json`; конкретная анимация одного блока редактируется в одном месте. Обязательные независимые блоки: появление и hover активных карточек меню; появление/исчезновение инструкции; поочерёдное появление трёх ячеек инфографики; анимация их графической части; возникновение «ГОЛ!» и совета; лёгкая вылетающая подпись о неудаче; изменение цифр HUD; заполнение индикатора голоса; отдельное появление большого финального заголовка, статистики и кнопок; попап ошибки микрофона; hover «Сброс»; реакция сетки/праздничного UI-эффекта без сдвига камеры.

Смена любого профиля `durationMs`, `delayMs`, `easing`, `opacity`, `yPx`, `scale` **не должна требовать правки GDScript конкретного UI-блока**. Время события гола/неудачи (`eventFeedback.durationMs`) настраивается отдельно от длительности отдельных микродвижений.

## 9. Сценарный контроль

Нельзя показывать инструкцию повторно перед каждым раундом; нельзя добавлять общий заголовок на стартовом экране; нельзя воспроизводить звуки или голос с микрофона; нельзя использовать постоянную модальную плашку на неудачах; нельзя закрывать подписью ключевые элементы поля. Тексты описывают только реальные действия игрока. Автоматический возврат на старт при молчании отсутствует.
